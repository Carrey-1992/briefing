🔥 今日最重要

Java4Shell 严重漏洞，需立即打补丁

CISA 紧急督促修复的 OpenJDK 远程代码执行漏洞（CVE-2026-114938，CVSS 9.2），影响目前最常用的 Java 17、21、25 和 27。对做 Java 的人来说，这比同日发布的英伟达创纪录财报更需要马上行动：先清点本机、服务器、容器镜像和第三方软件里的 JDK，升级到 17.0.21.1、21.0.13.1、25.0.5.1 或 27.0.1.1。

ℹ️ 覆盖北京时间 11-17 09:00 前后至 11-18 09:00。英伟达第三财季财报于北京时间 11-18 凌晨前后发布。不含融资。

大公司动态 2

英伟达第三财季营收 1158 亿美元，董事会公开排除黄仁勋回归

临时 CEO Colette Kress 主持黄仁勋离职后首次财报：第三财季（截至 10 月 25 日）营收 1158 亿美元，同比增长 103%、环比增长 20%，其中数据中心 1076 亿美元、同比增长 110%，GAAP 净利润 653 亿美元。第四财季展望 1300 亿美元（上下 3%），且未计入任何来自中国的数据中心计算营收；Vera Rubin NVL72 已开始出货。财报会上，董事长 Harvey Jones 明确表示董事会“不打算让黄仁勋重任 CEO”，也不回答辞职和调查相关问题。黄仁勋同日发表离职后首份声明，称若董事会认为符合股东、员工、公司和美国利益，他愿回归。

NVIDIA Newsroom ↗英伟达黄仁勋财报

微软 Ignite 推出自研专业模型，并向企业提供许可权重

在旧金山 Ignite 上，微软发布面向编程、安全和图像等任务的自研 MAI 模型，并宣布 MAI Licensed Weights：受信任的企业客户可获得模型权重、在 Azure 内用自有数据定制。旗舰编程模型 Code 2 及其更快的 Code 2 Flash 即日起可在 GitHub Copilot 和 Foundry 中使用；安全模型 Cyber 2 Flash 将进入微软安全产品。Mustafa Suleyman 对 Axios 表示，公司在通用前沿模型上已有进展，但未给出发布时间。

新模型和产品 2

OpenAI 发布 GPT-6.2 Astra 与 Sol

GPT-6.2 Astra 面向复杂专业工作，Sol 面向日常任务，即日起在 ChatGPT Work 和 Codex 向 Plus、Pro、Enterprise 和 Edu 用户开放，也可通过 API 调用。OpenAI 称 Astra 在 Agents’ Last Exam 上比 GPT-6 Astra 高 5.2 分，单任务成本不到其三分之一；API 定价为每百万 token 输入 8 美元、输出 40 美元，较上一代 Astra 降低 20%。Sol 价格与 GPT-6.1 Sol 相同（输入 2 美元、输出 10 美元）。公司同时称，这是首个对外发布、达到其“AI 自我改进”高等级门槛的模型，并因网络安全能力增强而收紧了相关防护。

SiliconANGLE ↗OpenAI模型

微软发布 MAI Code 2 与 Cyber 2 Flash

Code 2 主打企业日常编程中的多文件修改、调试和仓库级推理，Code 2 Flash 面向解释代码、小改动和快速迭代；微软称 Code 2 能达到 GPT-6.1 Sol 约 98% 的表现，价格约为其 40%，对 Claude Opus 5.5 则是约 96% 的表现、约 5% 的价格。Cyber 2 Flash 支持约 100 万 token 上下文，微软称在 CyberGym-E2E 漏洞发现任务上成功率 92.3%，略高于 GPT-6 Astra 的 91.5%，单任务成本不到其 2%；该模型将进入微软安全产品，计划 12 月中旬起在部分产品中替换现有模型。上述对比均为微软自家评测。

政策与研究 2

路透：中国机构系统用美国模型输出训练国产模型

路透查阅 300 多份论文、专利、公司公告、招聘和政府文件后称，蒸馏正从实验室走向工业应用：用 GPT-4、o1 等美国模型生成答案和代码，再训练更小的国产模型。该方法本身并不违法，但 OpenAI、Anthropic 认为这违反其使用条款；美方有官员称，工业级蒸馏是中美模型差距缩小的主要原因，中方人士则认为只是因素之一。中国今年 1 月“人工智能+制造”政策包将蒸馏列为支撑工业应用的手段，但并未要求蒸馏美国模型。报道指出，在本周美国进一步加强芯片出口管制后，这一做法的重要性可能还会上升。

Anthropic 将高危漏洞披露窗口从 90 天缩短至 30 天

Anthropic 更新协调漏洞披露政策：自 2027 年 1 月 1 日起新提交的高危和严重漏洞，公开披露窗口从 90 天改为 30 天，其他漏洞改为 45 天；若维护者 15 天内无回应将向外部协调方升级。公司称，模型已更能发现漏洞，同一缺陷被再次找到的可能性上升，90 天窗口不再合适。无法快速修复的关键基础设施或需改规范的问题仍可协商期限；正在进行中的报告沿用原时限。

Java4Shell：OpenJDK Base64 解码器曝严重远程代码执行漏洞

CVE-2026-114938（俗称 Java4Shell）是 x86-64 HotSpot 中优化版 Base64 解码器的内存损坏漏洞，CVSS 4.0 评分 9.2（严重）。美国网络安全与基础设施安全局（CISA）11 月 17 日督促立即打补丁：特制 Base64 输入可能导致 JVM 崩溃，并在最坏情况下造成未认证远程代码执行。受影响的是支持 AVX-512 VBMI 指令的 x86-64 机器上的 Java 17（自 17.0.6 起）、21、25 和 27；原生 ARM64 不受影响。Oracle 已在 11 月紧急安全补丁中修复，对应版本为 17.0.21.1、21.0.13.1、25.0.5.1、27.0.1.1，Temurin、Corretto 等衍生发行版同样需要升级。若暂时无法升级，可用 -XX:-UseBASE64Intrinsics 关掉该 intrinsic。请优先排查对外服务、容器镜像和捆绑了 JDK 的第三方软件。Oracle 公告
