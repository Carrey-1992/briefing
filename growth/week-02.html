讲义 · 四栏卡片

是什么

MCP（Model Context Protocol）是 AI 应用与外部上下文/工具之间交换上下文的协议。它只管协议本身，不规定 AI 应用怎么用 LLM 或怎么管理拿到的上下文。来源 ↗

参与者：Host 是 AI 应用（如 Claude Code、VS Code）；Host 为每个 Server 创建一个 Client，每个 Client 与对应 Server 保持一条专用连接；Server 是提供上下文的程序，可以在本地或远程运行。来源 ↗

两层：数据层基于 JSON-RPC 2.0，定义发现、原语（tools / resources / prompts）和通知；传输层负责连接建立、消息分帧和鉴权。来源 ↗

三类服务端原语：Tools 是 AI 可调用的可执行函数（如查数据库）；Resources 是提供上下文的数据源（如文件内容、表结构）；Prompts 是可复用的交互模板（如 few-shot 示例）。每类都有 */list 发现方法，Tool 用 tools/call 执行。来源 ↗

为什么这样设计

  • 一个 Server 一个 Client：连接隔离，一个 Server 出问题不影响其他；Host 统一协调。来源 ↗
  • 数据层与传输层分离：同一套 JSON-RPC 消息格式可以跑在 stdio 或 Streamable HTTP 上。来源 ↗
  • 两种传输：stdio 用于同一台机器上的进程间通信，没有网络开销，本地 Server 通常只服务一个 Client；Streamable HTTP 用 HTTP POST 发客户端消息、可选 SSE 做流式，适合远程 Server，支持 bearer token、API key 等标准鉴权，官方推荐用 OAuth 获取令牌。来源 ↗
  • 无状态与按请求携带元数据：当前官方架构页写明 MCP 是无状态协议，每个请求在 _meta 里带协议版本和能力，服务器不依赖之前的请求；Server 必须实现 server/discover，客户端可选在其他请求前调用。页面示例使用的协议版本是 2026-07-28。来源 ↗（注意：旧版本规范使用 initialize 握手，你读到的旧教程可能与此不同，以官方当前文档为准。）
  • 列表可动态变化：先 tools/list 再调用，配合 notifications/tools/list_changed 通知，工具集可以运行时变化。来源 ↗

什么时候会出问题

  • 通知可能丢：官方说明通知是 best effort，跨传输重连时尤其不保证送达，客户端还应定期轮询保持新鲜。来源 ↗
  • 版本不匹配：Server 不支持请求的协议版本时返回 UnsupportedProtocolVersionError 并列出支持的版本，客户端需重试。SDK 版本与规范版本对不上是常见坑。来源 ↗
  • 已弃用能力：从协议版本 2026-07-28 起，客户端原语 Sampling 和 Logging 被标为弃用；新实现应直接对接 LLM 提供商 API，日志写 stderr（stdio）或用 OpenTelemetry。来源 ↗
  • stdio 下乱打日志：stdio 用标准输出传协议消息，往 stdout 打印日志会破坏消息流；应写 stderr（同上官方建议）。
  • 工具描述写得差：模型靠 name / description / inputSchema 决定是否和如何调用；名字含糊、参数不清会导致调错或不调。这与第 1 周的 ACI 原则一致。来源 ↗
  • 远程 Server 的安全：远程 Server 要做鉴权；工具能执行真实操作，权限要最小化。

怎么验证过

完成实验后填写：你的 Server 暴露了哪几个 Tool，tools/list 的返回长什么样；AI 第一次是否调对了；你改了哪处描述后调用更准确。未做实验前保持空白。

回忆题

  1. Host、Client、Server 分别是什么，数量关系如何？
    参考答案

    Host 是 AI 应用；Host 为每个 Server 创建一个 Client，Client 与 Server 一对一保持专用连接；一个 Host 可连多个 Server。

  2. MCP 的两层各负责什么？
    参考答案

    数据层：基于 JSON-RPC 2.0 的消息结构与语义（发现、原语、通知）；传输层：连接建立、消息分帧、鉴权（stdio / Streamable HTTP）。

  3. Tools、Resources、Prompts 的区别？各举一例。
    参考答案

    Tools：可执行操作，如查询数据库；Resources：只提供上下文数据，如表结构；Prompts：可复用交互模板，如 few-shot 示例。

  4. stdio 与 Streamable HTTP 怎么选？
    参考答案

    本地同机进程、单客户端用 stdio，无网络开销；远程、多客户端用 Streamable HTTP，可用标准 HTTP 鉴权，官方推荐 OAuth。

  5. 为什么 stdio Server 不能往 stdout 打日志？收到 list_changed 通知后客户端该做什么？
    参考答案

    stdout 承载协议消息，日志会破坏消息流，应写 stderr。收到通知后重新调用 tools/list 刷新工具列表；通知是 best effort，还要定期轮询。
