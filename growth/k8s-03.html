模块3 · 多租户与配额

建议第 3 周完成 · 工作日每天 30 分钟读讲义 · 周末前半天做实验 · 已完成 0 项

目标

能讲清 Namespace、ResourceQuota、LimitRange、RBAC 各管什么、怎么配合；能触发并读懂一次配额超限；知道软隔离（命名空间）和更强隔离（虚拟集群等）的区别。

讲义 · 四栏卡片（读完一栏点 ✓）

是什么

Namespace 在一个集群内隔离一组资源的名字作用域，是多租户的基本单位。Namespace ↗

ResourceQuota 限制一个命名空间的资源总量（如 requests.cpu、limits.memory、Pod 数量等）。ResourceQuota ↗

LimitRange 约束命名空间内单个 Pod/容器的资源最小值、最大值，并可给没写的容器注入默认 requests/limits。LimitRange ↗

RBAC 用 Role/ClusterRole 定义权限，用 RoleBinding/ClusterRoleBinding 授给用户、组或 ServiceAccount。RBAC 鉴权 ↗

为什么这样设计

配额在准入阶段拦截：创建或更新违反配额时，控制平面直接以 HTTP 403 Forbidden 拒绝，并给出违反了哪条约束。ResourceQuota ↗这样超额请求根本不会进入调度队列。

如果命名空间对 cpu/memory 启用了配额，每个新 Pod 都必须写 requests 或 limits，否则可能被拒；所以官方建议配合 LimitRange 注入默认值。ResourceQuota ↗

官方多租户文档把模型分为“多团队”和“多客户”，隔离手段从命名空间级的控制平面隔离，到每租户独立控制平面（虚拟控制平面）不等，隔离越强成本越高。K8s 多租户 ↗

什么时候会出问题

  • 没写 requests 被拒：开了 cpu/memory 配额却没有 LimitRange 默认值，用户的 Pod 创建失败。ResourceQuota ↗
  • Deployment 看似成功：Deployment 本身创建成功，但 ReplicaSet 创建 Pod 被配额拒绝，错误只出现在 ReplicaSet 的事件里，容易漏看。
  • 配额不等于资源保证：配额总和可以大于集群实际容量，配额只限上限不预留资源。
  • RBAC 过宽：随手绑定 cluster-admin 会让命名空间隔离失效。RBAC 鉴权 ↗

未核实：“配额总和可以超过集群容量”按 ResourceQuota 文档的语义推断，未找到原句。

怎么验证过

实验后填写：① 超限时的 403 错误原文；② Deployment 超限时去哪里看到错误；③ 用 kubectl auth can-i 验证 ServiceAccount 权限的结果。

动手实验（家里电脑，周末半天）

以下命令未在本机运行验证。

kubectl create namespace team-a
cat <<'EOF' | kubectl apply -n team-a -f -
apiVersion: v1
kind: ResourceQuota
metadata: {name: q}
spec:
  hard:
    requests.cpu: "1"
    requests.memory: 1Gi
    limits.cpu: "2"
    limits.memory: 2Gi
    pods: "3"
---
apiVersion: v1
kind: LimitRange
metadata: {name: lr}
spec:
  limits:
  - type: Container
    default: {cpu: 500m, memory: 256Mi}
    defaultRequest: {cpu: 250m, memory: 128Mi}
EOF
kubectl describe quota q -n team-a

1. 直接触发超限（单个 Pod）

kubectl run huge -n team-a --image=nginx --overrides='{"spec":{"containers":[{"name":"huge","image":"nginx","resources":{"requests":{"cpu":"2"},"limits":{"cpu":"2"}}}]}}'
# 期望：Error from server (Forbidden): ... exceeded quota ...

2. 通过 Deployment 触发（错误藏在 ReplicaSet）

kubectl create deployment web -n team-a --image=nginx --replicas=5
kubectl get deploy,rs,pod -n team-a          # 只起来部分副本
kubectl describe rs -n team-a | grep -A3 Events
kubectl describe quota q -n team-a           # Used 与 Hard 对比

3. RBAC：只读 ServiceAccount

kubectl create serviceaccount viewer -n team-a
kubectl create role pod-reader -n team-a --verb=get,list,watch --resource=pods
kubectl create rolebinding viewer-rb -n team-a --role=pod-reader --serviceaccount=team-a:viewer
kubectl auth can-i list pods -n team-a --as=system:serviceaccount:team-a:viewer    # yes
kubectl auth can-i create pods -n team-a --as=system:serviceaccount:team-a:viewer  # no

简述（不做实验）：命名空间是软隔离；需要租户各自有独立控制平面时，可了解官方多租户文档中的虚拟控制平面方案。K8s 多租户 ↗

未核实：分层命名空间（HNC）、vcluster 等具体项目本次未读文档，不展开。

回忆题（先答再展开）

  1. ResourceQuota 和 LimitRange 分别管什么？
    参考答案

    ResourceQuota 管命名空间的总量上限；LimitRange 管单个 Pod/容器的最小/最大值并可注入默认 requests/limits。

  2. 超出配额时 API 返回什么？发生在哪个阶段？
    参考答案

    HTTP 403 Forbidden，带违反约束的说明；发生在 API Server 的准入阶段，请求不会被持久化，也不会进入调度。

  3. 为什么开了 cpu 配额后，没写 requests 的 Pod 会失败？如何解决？
    参考答案

    启用 cpu/memory 配额后每个新 Pod 必须指定对应的 requests 或 limits；用 LimitRange 设置默认值即可。

  4. Deployment 副本没起够，但 kubectl apply 没报错，去哪查？
    参考答案

    describe 对应的 ReplicaSet 看 Events，那里有创建 Pod 被配额拒绝的错误；再 describe quota 对比 Used/Hard。

  5. Role 与 ClusterRole、RoleBinding 与 ClusterRoleBinding 的区别？
    参考答案

    Role 作用于单个命名空间，ClusterRole 是集群范围（也可以被 RoleBinding 引用、只在某命名空间生效）；RoleBinding 在命名空间内授权，ClusterRoleBinding 在整个集群授权。
